# GameX storefront gallery update

## What changed
- Homepage Products: five cards per row on extra-large (1280px+) screens; ten products in the default two rows. Existing small-screen columns remain responsive.
- Product/build cards: slightly smaller price banners.
- Admin > Products and Admin > Custom Builds: the existing **cover image** upload/URL field is kept. Under it, the new **Additional gallery photos** editor lets you add up to 9 more files or external URLs, remove images, and reorder them. Each file may be JPG/PNG/WebP up to 5 MB. Uploaded files are stored in your existing Cloudinary account.
- Product/build detail pages and their quick-view modal: image thumbnails, previous/next browsing, full-screen enlarged viewer, +/- zoom (up to 400%), Escape/arrows keyboard shortcuts, and double-click to zoom.
- Product/build quick-view and detail galleries: click/tap the main image to open the full-screen viewer; click/tap again or use +/- controls to zoom.
- Mobile quick-view: the whole modal now scrolls normally, so the image moves away with the content instead of staying pinned while details scroll underneath.

## IMPORTANT: database migration
The application now reads/writes `products.images` and `custom_builds.images` PostgreSQL `text[]` columns. **Apply the migration before deploying the new application code.** The migration is included at `drizzle/0014_product_build_galleries.sql` and registered in `drizzle/meta/_journal.json`.

From the project root with DATABASE_URL configured:

```bash
npm install
npx drizzle-kit migrate
npm run typecheck
npm run build
```

If your existing migration tracking system differs or 0014 was already applied manually, execute the two idempotent `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` statements from `drizzle/0014_product_build_galleries.sql` in your Neon SQL editor instead. Check migration history before rerunning old migrations.

## Configuration and deployment
- Restore your own `.env.local` file locally or set the secrets in your hosting platform.
- Keep your existing `DATABASE_URL`, `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` configured.
- `node_modules` and `.next` are generated by the normal install/build process and are not included.
- The Server Actions upload request size in `next.config.ts` has been raised to 52 MB to support multiple 5 MB photos. If your hosting platform has a smaller body-size limit, consider direct-to-Cloudinary uploads before using large photo batches.
- Existing `image` fields are preserved; `images` stores the complete gallery including the primary image for new/updated listings. Existing listings with empty `images` automatically display their original cover image until they are edited.

## Quick manual smoke test after migration/deployment
1. Create a product with a cover and 2 extra photos. Save and verify 3 thumbnails in quick view and detail page.
2. Edit the product, remove one additional photo, reverse the remaining extras, change the cover, and save.
3. Repeat for Custom Builds.
4. On a desktop at least 1280px wide verify 5 product cards per row, and on mobile verify responsive columns.
5. Zoom photos in the full-screen viewer and test keyboard and touchscreen buttons.
